03 / GRAPHRAG PIPELINE

How the Agent Answers Questions

Instead of passing raw text to Claude, the agent retrieves a structured subgraph from Neo4j and injects it as grounded context — eliminating hallucination and enabling citation-ready answers.

⚡ Agentic Q&A Flow

1

User asks a clinical question — e.g. "What drugs compete with Semaglutide in obesity trials?"

2

Entity extraction — drug / disease / sponsor is identified from the question string.

3

KG subgraph retrieval — build_graphrag_context() fires a multi-hop Cypher query returning Drug→Study→Condition→Sponsor paths.

4

Context injection — structured paths are serialised as text and prepended to Claude's system prompt.

5

Claude generates answer — grounded only in the retrieved subgraph. Every claim is traceable to a real NCT ID.

Python · graphrag_context # Build structured context from KG def build_graphrag_context( kg: KGClient, drug: str = None, disease: str = None, ) -> str: query = """ MATCH (i:Intervention) <-[:USES_INTERVENTION]-(st:Study) WHERE toLower(i.name) CONTAINS $drug MATCH (st)-[:STUDIES]->(c:Condition) MATCH (st)<-[:SPONSORS]-(s:Sponsor) RETURN i.name, st.nct_id, c.name, s.name LIMIT 50 """ rows = kg.query(query, {"drug": drug}) return _format_context(rows)

04 / GRAPH SCHEMA

Knowledge Graph Structure

The schema encodes clinical trial semantics. Each relationship is directional with a defined meaning, enabling precise multi-hop traversal.

NODE LABELS
StudyRegistered clinical trial (NCT ID, phases, status, enrollment)
InterventionDrug, device, or procedure being tested
ConditionDisease or condition targeted by the study
SponsorOrganisation funding the trial (+ class)
ArmTrial arm: experimental, placebo, comparator
LocationFacility conducting the trial (country, city, lat/lon)
RELATIONSHIPS
SPONSORS →Sponsor funds/leads the Study
STUDIES →Study targets a Condition
USES_INTERVENTION →Study tests a Drug or device
HAS_ARM →Study contains a trial Arm
CONDUCTED_AT →Study runs at a Location
